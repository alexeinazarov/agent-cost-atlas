# Agent Cost Atlas

Reproducible discovery and evaluation of open-source software concerned with the operating economics of AI agents and LLM workflows.

## Objective

Agent Cost Atlas maps public open-source software related to:

- agent and LLM operating-cost estimation;
- future-spend forecasting and projection;
- pre-execution cost estimation;
- runtime budget enforcement and spend governance;
- agentic FinOps and related economic controls.

The project separates **discovery** from **competitor classification**.

Known competitor repository names are not seeded into the discovery protocol. Method-specific mathematical terms are likewise not used as discovery queries. A method is recorded only when it appears naturally in retrieved public evidence.

## Method

The research pipeline is:

```text
GitHub repository search
        ↓
deduplication and candidate ranking
        ↓
README evidence collection
        ↓
machine-generated discovery snapshot
        ↓
manual relevance adjudication
        ↓
precision / recall evaluation
        ↓
verified open-source competitor set
```

`config/search.toml` is the inspectable discovery protocol. It records the search vocabulary, GitHub API settings, pagination limits, ranking parameters and retrieval modes.

Each query is executed using both GitHub **best-match** relevance and **recently updated** ordering. Generated results disclose GitHub's reported result count, the number actually retrieved, pagination depth, and whether collection was capped.

The automated relevance score is a retrieval aid. It is **not** treated as a competitor judgment.

## Evaluation

The next phase assigns human relevance judgments to retrieved candidates before any competitor-count or completeness claim is made.

A relevant direct candidate must concern the economics generated by the AI/LLM/agent workload itself, rather than merely using an agent to analyse an unrelated economic domain.

Manual adjudication will support measurement of:

```math
\mathrm{Precision}
=
\frac{\text{relevant retrieved repositories}}
     {\text{retrieved repositories}}
````

and, against an independently assembled pre-existing reference set:

```math
\mathrm{Recall}
=
\frac{\text{known relevant repositories retrieved}}
     {\text{known relevant repositories}}
```

The pre-existing reference set remains outside the discovery configuration so that it can serve as a held-out recall check rather than contaminating the retrieval protocol.

## Provenance

Each successful snapshot records:

- run timestamp and source commit;
- configuration SHA-256;
- GitHub API version;
- matched discovery searches;
- repository metadata and stable repository ID;
- README evidence and README SHA;
- default branch and observed head SHA;
- query-level collection coverage;
- search and repository-level collection failures.

These fields are intended to support a later longitudinal phase in which scheduled runs can identify repository changes without redesigning the discovery schema.

## Reproduce

### GitHub

Open:

**Actions → Discover open-source agent-cost projects → Run workflow**

The workflow performs linting, formatting validation, compilation and tests before network discovery. A successful discovery snapshot is validated and committed back to the repository.

### Local checkout

```bash
PYTHONPATH=src python -m agent_cost_atlas discover \
  --config config/search.toml \
  --results-dir results
```

Configuration resolution does not depend on the caller's working directory; an explicit `--config` path is also supported.

## Methodological basis

The research design is informed by established information-retrieval and systematic-search methodology rather than treating keyword matches as ground truth:

- Manning, C. D., Raghavan, P. & Schütze, H. *Introduction to Information Retrieval*, Cambridge University Press — relevance judgments, precision/recall, ranked retrieval and held-out evaluation.
- NIST Text REtrieval Conference (TREC) methodology — retrieval runs, relevance judgments and pooled assessment.
- Rethlefsen, M. L. et al. (2021), *PRISMA-S: an extension to the PRISMA Statement for Reporting Literature Searches in Systematic Reviews*, *Systematic Reviews* 10:39 — transparent and reproducible reporting of search procedures.

PRISMA-S is used here as methodological guidance for search transparency; Agent Cost Atlas is not presented as a PRISMA systematic review.
